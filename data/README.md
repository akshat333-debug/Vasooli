# Sample data

Both files here are generated, not hand-written, and both come from the same
seed (`42`) the rest of this project's numbers are built on — so what you see
here is exactly what `README.md` §4 describes, not a separate curated example.

| File | What it is | Regenerate with |
|---|---|---|
| `sample_batch.json` | 100 synthetic at-risk subscriptions — the raw input the engine decides over. Same generator, same seed, as every other artefact in this repo. | `uv run vasooli seed -n 100 --seed 42 --json` |
| `sample_worklist.csv` | The escalation worklist the sequencer arm produces from that batch: one row per unrecovered subscription, largest amount first, with the route and the concrete next step. | `uv run vasooli worklist --no-llm --out data/sample_worklist.csv` |

**This is synthetic data**, generated by `vasooli/sim/seed.py` from named,
documented assumptions in `vasooli/sim/model.py` — not measured from Razorpay
or any bank. See `README.md` §12 ("What is real and what is simulated") for
exactly which parts of this project are assumption and which are real
Razorpay test-mode API calls.

Every other number, chart and JSON file in this repo (`BATCH_REPORT.txt`,
`EXPERIMENTS.txt`, `web/data/batch.json`, the live interface) is derived from
this same seed. Nothing here is a special case built for this folder.
