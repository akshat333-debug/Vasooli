1. SEED SWEEP - is the headline an artefact of seed 42?
----------------------------------------------------------------------------
  sequencer led on recovery-per-attempt in 40/40 seeds
  median delta  +114.3%
  5th pct       +63.2%
  95th pct      +216.0%
  worst seed    +50.4%
  losing seeds  none

  1b. GROSS RECOVERY - the same sweep without the compliance adjustment
  sequencer led on GROSS recovery-per-attempt in 40/40 seeds
  median gross delta  +114.3%
  gross losing seeds  none
  The two bases now agree, because nothing above the RBI cap is
  recovered by either arm - the network declines it. The adjustment is
  no longer doing any work, which is a better answer than defending it.

  1c. TOTAL RUPEES COLLECTED - budget ignored, the crude question
  sequencer collected more money outright in 25/40 seeds (1 tied, 14 lost)
  median delta  Rs 1,047.00   worst seed  Rs -12,695.00
  Stated plainly because it is the weakest number here and a reader
  would find it anyway. Everything above is rupees PER ATTEMPT, and
  that is the metric this project argues for: the retry budget is the
  scarce resource, three deep and non-refilling, so an arm that
  collects the same money on half the budget has more left for next
  cycle. Judge that claim on the rate. The total is offered so the
  choice of metric is visible rather than convenient.

2. ATTRIBUTION - is the advantage timing, or refusal?
----------------------------------------------------------------------------
  A  baseline                    Rs   303.07/attempt (159 attempts)
  B  refusals, naive timing      Rs   589.47/attempt (82 attempts)
  C  refusals + optimal timing   Rs   652.99/attempt (76 attempts)

  from REFUSING  Rs  286.41/attempt (82% of the gain)
  from TIMING    Rs   63.52/attempt (18% of the gain)

  Refusing doomed attempts is the dominant mechanism. Timing helps, but
  it is the smaller half by a wide margin - worth saying plainly rather
  than implying the grid search is what makes this work.

4. RULE ABLATION - what is each stopping rule worth?
----------------------------------------------------------------------------
  rule  name                                    attempts   wasted   above cap  refusals
     0  all rules on                                76.3     44.2           0       0.0
     1  Retry budget exhausted                      76.3     44.2           0       5.9
     2  Terminal failure class                      81.2     49.1           0       0.0
     3  Mandate not active                          76.3     44.2           0       0.0
     4  Failure unclassified                        81.7     49.5           0       0.0
     5  Above the mandate's own cap                 83.6     51.5           0       0.0
     6  Above the RBI standard cap                  76.3     44.2           0       4.8
     7  Mandate expires before notice elapses       76.3     44.2           0       0.0

  Row 0 is every rule on. Each other row is that rule switched off.
  Higher attempts or wasted counts are the cost of removing it.

  'above cap' is Rs 0 on every row, INCLUDING rule 6 off. That is
  defence in depth, not a broken ablation: with the stopping rule gone,
  the money-side breaker refuses the debit at the action boundary and
  the network would decline it anyway for want of AFA. The cost of
  losing rule 6 shows up one layer down, in the refusals column.

5. CALIBRATION - do the reported probabilities mean anything?
----------------------------------------------------------------------------
      bucket      n   predicted   observed      gap
     0.0-0.2    340       0.166      0.165   -0.001
     0.4-0.6    889       0.512      0.474   -0.038
     0.6-0.8    752       0.633      0.582   -0.051
     0.8-1.0    185       0.810      0.670   -0.140

  Internal consistency only: predictions and outcomes come from the same
  assumed model, so agreement shows the scheduler reads its own model
  correctly. It is not evidence about real banks.

  NOT WELL CALIBRATED AT THE TOP. The 0.8-1.0 bucket predicts 0.810
  and observes 0.670, over-confident by 0.140 across 185 attempts.
  The scheduler is most wrong exactly where it is most sure, which is the
  worst place to be wrong: those are the attempts it most wants to spend.
  Cause is the per-attempt decay in sim/model.py compounding faster than
  the scorer assumes when it reads the same curve back. It does not change
  the arm comparison - both arms are scored by this identical model - but
  a confidence this system reports should not be read as a probability.
